# 设计给人看的 graph 查看界面

Type: prototype
Status: resolved
Blocked by: issue:0099:19, issue:0099:22

##### Question

用户 11-13 在 D26 中要求: 1.0 要有给人看的 graph 查看界面, "以人类能读懂的方式展现, 而不是一个屏幕上摆上几百个节点和几千根连线", 从最上层开始看, 需要时才看下面的细节. [定义规则到 graph 的转换与 Engine 按 graph 执行](22-define-rule-to-graph-conversion.md) 已把 graph 分层为有名字的子流程 (头部有说明, 输入, 返回值与必经边, 用 `call` 调用), 并为每个子流程生成路径摘要. 查看界面怎样从顶层子流程开始按需展开: 一层显示什么 (子流程说明, 节点与边, 返回值, 路径摘要), 怎样进入被调子流程和返回, 怎样按节点全名, 关键词或参数定位, 怎样显示一个实例当前所在的节点和走过的路径? 它放在哪里: [确定 Engine 对话入口的形态](19-decide-conversation-entry-form.md) 的网页入口中的一页, 还是 graph 命令行工具生成的静态页面? 首版只读还是也能改 graph? 用一个以试转换的 commit 流程 (4 层, 74 个节点) 为数据的可丢弃原型检验, 单屏节点数不超过一个子流程 (试转换中最多 11 个).

## Answer

11-18 worker (任务 v1-24) 用可丢弃的 HTML 原型检验, 交 Main Agent 综合. 数据是 [commit 流程的分层逐节点 JSONL 试转换](../research/conversion-trial/) (16 个子流程, 74 个节点, 4 层), 加 7 条虚构的上层记录 (仓库层 4 条, 本机层 3 条, 其中 2 条过期) 和一个停在待答事项上的样例实例. 原型有三个结构不同的变体 (逐层列表, 分层图, 路径摘要加调用树), 在 390 与 1280 像素宽下截图并做点击核对; 原型不进仓库. 首版只读还是也能改 graph 是方向性取舍, 下文按建议写, 由 Main Agent 交用户确认 (见 Comments).

### Placement

- 查看界面是 [确定 Engine 对话入口的形态](19-decide-conversation-entry-form.md) 的 HTML client 中的一页 ("流程"), 桌面与手机共用. 不另做命令行工具生成的静态页面: 静态的流程说明已由 22 的命令行工具生成的 Markdown (节点说明与路径摘要) 覆盖, 而实例叠加, 待答事项和过期记录都要 Engine 的实时状态与命令接口 (07).
- 数据全部来自 Engine (合并后带层的 graph, 路径摘要, 07 的实例状态与栈); 页面不自己解析 JSONL, 也不自己合并各层.

### One subflow per screen

- 一屏只显示一个子流程: 头部 (名称, 说明, 返回值及含义, 入口, 节点数, 调用方, 本子流程的上层记录数), 下面是节点. 试转换中最大的子流程 11 个节点, 一屏放得下.
- 默认视图是逐层列表: 节点按从入口出发的行走顺序排列, 每个节点一行说明, 下面逐条列出它的边 (结果值与去向, 去向为 `return:` 时写 "返回 X"); 调用节点带 "进入" 按钮; "详情" 展开节点全名, 原语, 参数, 指令或规则. 理由: 390 像素宽时只有列表可读. 分层图在 1280 宽下适合边少的子流程 (如 `audit-round`), 但在 `implementation-commit` 这类有 4 个返回值, 多条边汇向 "用户停止" 的子流程里, 边与标签交叉重叠; 390 宽时节点名被截断.
- 图只作 900 像素以上的可选视图 (分层布局, 回边画虚线, 返回值画成终端). 路径摘要是每个子流程的第二个视图: 入口到每个返回值的 `节点:结果值` 序列与回环, 经过调用节点时可以就地展开一层; 它主要给审核用 (见 Readability supplement 节).
- 进入与返回: 面包屑显示从顶层到当前子流程的调用链, 每级可点, 地址带子流程名, 可以刷新和分享 (浏览器后退回到上一级是设计建议, 原型未验证). 子流程被多处调用时, 面包屑按进入时的路径显示, 头部列出全部调用方. 调用树只在宽屏作侧栏.

### Locating

- 一个搜索框, 匹配节点全名或其片段 (如 `audit-round/freeze`), 子流程名, 参数名 (如 `callbackThresholdMs` 命中引用它的节点), 原语名, 以及说明, 指令和规则中的关键词. 每条结果显示节点全名, 类型和命中处的片段; 选中后打开所在子流程并定位到该节点.

### Instance overlay

- 实例开关选一个运行中或已结束的实例. 打开后: 当前节点标 "当前" (在等用户时标 "当前: 等你回答"), 走过的节点标 "走过" 和次数, 走过的边标勾号; 调用链上的子流程同样标出; "到当前节点" 直接打开栈顶子流程. 设计建议 (原型未验证): 实例的步骤时间线 (时间, 节点全名, 结果值) 在宽屏作侧栏, 手机上折叠.
- 实例停在待答事项时, 流程页顶部显示一行横幅 (实例, 节点, 问题标题, "去回答"); 回答在待答页进行, 流程页不重复整张问题卡.

### Layers and stale records

- 节点与边标出所在层: 管理层不标, 仓库层标 "仓库", 本机层标 "本机" (文字加颜色, 颜色不是唯一载体). 改接过的边同时显示原去向. 追加给 Agent 节点的规则, 目标节点上的预置答案 (情况键, 答案, 原因) 都在详情中带层标记. 被上层改边绕过而不可达的节点标 "不可达".
- "上层记录" 页按层列出全部记录 (编号, 种类, 目标节点, 内容, 状态). 过期记录标 "过期, 未生效", 显示写入时与现在的节点哈希和写入时的 ARW 版本, 点了进入 22 的 Layers 节所说的过期记录待答事项.

### Option comparison table

- 待答事项的选项用表格展示: 每行一个选项, 列是 "选了之后" 与各个对比维度, 推荐项标 "推荐"; 手机上表格在自己的框内横向滚动, 首列固定. 选择用单选按钮组, 不用下拉; "没看懂" 按 19 的规定.
- 为此 22 的 Graph shape 节 `ask-user` 的 `decision` 加两个可选字段: `aspects[]` (对比维度名) 和每个选项的 `cells[]` (按 `aspects` 的顺序, 每格一个短句, 没有内容写 `-`). 没有 `aspects` 时表格只有 "选项" 与 "选了之后" 两列.

### Read-only first version

- 建议首版只读: 查看界面不改 graph 和上层记录. 能操作的只有已经存在的待答事项: 回答问题, 处理过期记录 (重新确认或删除), 撤销一条预置答案; 都经 07 的命令接口由 Engine 写入, 与在对话中处理相同. 新的补丁, 新节点与预置答案仍由会话经命令行工具写 (22, 23), 写入时运行合并后的校验. 理由: 改 graph 就是改规则, 要经静态校验, 路径摘要复核和提交流程; 页面内的编辑器还要另做表单, 校验反馈和并发冲突处理, 首版收益小.

### Readability supplement

- 两题各配一道同样大小, 应判正确的对照题, 共 4 题: (1) `implementation-commit` 的大改写 (改名, 改描述, 重排键序) 中藏着 `needs-round` 与 `hook-failed` 去向互换; (2) 仓库层补丁为 "去掉术语检查" 把 `callbacks:ok` 改接 `hints`, 绕过整个 `precheck`. 文本组拿现行提交 Skill, validation Skill 与采用方根 `AGENTS.md` 上的等价改动, graph 组拿试转换 graph, 层规则摘要与改动前后的路径摘要; 每组 3 个 Sonnet (high) 会话, 题序各不相同, 标准答案先于运行写定.
- 结果: 两组都是 12/12, 每题判定与理由都命中要点; graph 组每会话平均约 44 秒, 0.15 美元, 文本组约 35 秒, 0.12 美元. 题目点明了改动意图, 两组都在上限, 不能区分两种材料; 与 22 的读改实测一致, graph 加路径摘要不比文本难审. graph 组 3 个会话都指出上层补丁不能改 `args`, 所以只能不改或另想办法; 文本组 3 个会话都给出了更好的替代 (只跳过 validation Skill 中的术语检查命令).
- 补丁绕过整个节点的错误, 合并后的校验拦不住 (该子流程没有 `guarantees`), 路径摘要的前后差异能直接显示它. 建议 22 的 Layers 节 "审核包附受影响子流程的路径摘要" 附改动前后两份, 查看界面的路径摘要视图也能按一条上层记录显示前后差异.
